## 为什么需要它

论文格式被打回，通常不是内容问题，而是这几件小事：📄 目录页码和正文对不上 ｜ 🧾 页眉串了节 ｜ 🔢 图表编号从头到尾连着数 ｜ 📐 摘要题头字号差一号。这些都能被"看出来"，也都能被"查出来"。

这个技能包把两套要求写成三层：`SKILL.md` 负责判断你要做什么（并先问用哪套口径），`references/` 存细则，`scripts/` 直接对 `.docx` 做离线自检——**改完就能验，不用靠肉眼猜**。

## 四个亮点

| | 亮点 | 说明 |
| --- | --- | --- |
| 🤖 | **可机检** | `scripts/check_docx.py` 离线读 `.docx`，覆盖页面、页码分段、页眉、字号、标题编号、题注、目录、摘要、参考文献、AI 工具使用声明、装订顺序等 15 类检查，输出 FAIL / WARN / PASS，每条都指到具体条款 |
| 🧭 | **两套口径一键切换** | `--profile zhonghua-cs-2023`（默认）与 `--profile school-436`，差异（左右页边距、页眉内容、标题字体、表格边框…）逐条写在 `rules.json` 里，不在代码里硬编码 |
| 📐 | **图表编号强制规则** | `图X-Y` / `表X-Y`：每章从 1 重编，图题在图下、表题在表上，题末不加标点，正文必须先引用——脚本逐条核对 |
| 🤝 | **规范自相矛盾时明说** | AI 工具使用声明的位置在三处条款里说法不一致，技能不替学院拍板，如实列出冲突并让你去问指导教师 |

## 快速开始

```bash
# 1. 装到技能目录（三选一）
git clone <this-repo> ~/.codex/skills/ynufe-thesis-format         # Codex
git clone <this-repo> ~/.agents/skills/ynufe-thesis-format       # 通用 agents 技能目录
git clone <this-repo> ~/.claude/skills/ynufe-thesis-format       # Claude Code

# 2. 对你的论文跑一次自检（Python 3.9+，只用标准库）
python scripts/check_docx.py "我的论文.docx"
python scripts/check_docx.py "我的论文.docx" --json
python scripts/check_docx.py "我的论文.docx" --profile school-436
python scripts/check_docx.py --list-profiles
python scripts/check_docx.py --list-rules
```

脚本**只读** `.docx`，不修改、不上传任何内容。安装后重新开一个会话，技能才会被加载。

## 它能替你查什么

| 规则组 | 检查内容 | 依据 |
| --- | --- | --- |
| `page.*` | A4 开本、页边距（本专业规范 上下 2.54cm／左右 2.5cm；436 左右 3.17cm）、页眉 1.5cm、页脚 1.75cm、1.5 倍行距 | 规范 第七章三（一）（三）；第十五条（三） |
| `page.numbering` | 前置部分罗马数字、正文至附录阿拉伯数字并从 1 重新开始、封面不编号 | 规范 第七章三（五）；第十五条（三） |
| `header.*` | 除封面扉页外每页有页眉；本专业规范为固定文字「云南财经大学中华职业学院本科毕业设计（论文）」，436 为 `STYLEREF "标题 1"` | 规范 第七章三（一）；第十五条（五） |
| `style.*` | 正文小 4 宋体 + Times New Roman、首行缩进 2 字符、题目 ≤25 字 | 第十五条（三）、第六条（二） |
| `heading.*` | 四级标题字体（本专业规范：黑体三号／小三／四号／小四加粗）、大纲级别；编号形式与上下空行按 436 口径 | 规范 表 7-2；第十五条（三）（四） |
| `abstract.*` `keywords.*` | 「摘　要」题头（本专业规范黑体三号、436 小 2 加粗宋体）、摘要 300—500 字、关键词 3—5 个（本专业规范用分号）、外文摘要 Times New Roman | 规范 表 7-2、第七章二（一）；第十五条（二）、第六条（三） |
| `toc.*` | 「目　录」题头（本专业规范三号黑体）、TOC 域层级（本专业规范至三级、436 两级）、条目与页码 | 规范 第七章二（二）；第十五条（一）、第六条（四） |
| `caption.*` | 编号格式、图题在图下 / 表题在表上、每章连续、正文先引用；本专业规范 表题黑体小四加粗、图题宋体五号 | 规范 第七章三（四）；第十五条（九）（十） |
| `table.borders` | 本专业规范：六条边线齐全的**完整边框**；436：三线表（无左右边线、上下 1.5 磅、内线 0.5 磅） | 规范 第七章三（四）；第十五条（九） |
| `note.*` `reference.*` `body.*` `ai.*` `binding.*` | 脚注按页编号、参考文献 ≥20 篇且序号连续、文献构成（期刊与著作 ≥60%、近 5 年 ≥50%）、正文 ≥10000 字、AI 工具使用声明专节、装订顺序 | 规范 第三／六／七／八章；第六条、第十五条、第二十五条 |

跑完会得到两类提示：

```text
=== 必须修改（FAIL）===
[page.margin] 偏差 left=1800, right=1800（应 top/bottom=1440、left/right=1417 twips）  —— 第 1 节
[header.content] 正文节页眉应统一标注「云南财经大学中华职业学院本科毕业设计（论文）」，实际内容=['一、绪论']  —— 第 6 节
[caption.font] 表题 sz=21（应 24）：表3-1 现状问题汇总表  —— 块 163
[ai.disclosure] 未找到「人工智能工具使用声明」专节  —— 

=== 建议确认（WARN）===
[table.borders] 缺少 left 边线（本专业规范要求完整边框）；缺少 right 边线  —— 表块 164
```

脚本不渲染版面，所以**页眉串节、目录点线、图表跨页断开**这些仍要导出 PDF 转图逐页看——技能里把这步写成了硬性交付条件。

## 几条容易被忽略的规则

- **标题编号后缀**：标题自动编号的后缀必须是"无"（`suff=nothing`）。默认的制表符后缀会让目录条目与点线之间空出一大截。
- **三级、四级编号**：`1` 不带尾点；四级是 `（1）` 而且是**全角括号**，并且四级标题样式必须挂上编号，否则正文里根本没有第四级序号。
- **页码分段靠分节**：前置部分罗马数字、正文从 1 重来，只能靠分节符实现；封面单独成节且不引用页眉页脚，才是真的没有页码。
- **本专业规范口径下**：「摘　要」和「目　录」题头都是黑体三号；但**表题是黑体小四加粗、图题是宋体五号**——两行口径不同，别"统一"掉。
- **图题在图下、表题在表上**，题末一律不加标点；正文先写"如图X-Y所示"，图再出现。
- **查重低于 20%**；送检文件名按「学院+专业班级+学号+作者姓名+指导教师姓名+题目」。

## 常见问题

**Q：会上传我的论文吗？**
不会。技能本身没有网络请求，检查脚本在你本机读 `.docx`，只读不写。

**Q：标题到底用宋体加粗还是黑体？**
看口径。默认的 `zhonghua-cs-2023` 口径下，专业规范表 7-2 已经把四级标题定成**黑体三号／小三／四号／小四并加粗**，不需要纠结。436 号文第十五条（三）原文是「正文中标题用小 4 加粗宋体」，而部分学院模板按「一级二级黑体 4 号、三级四级黑体小 4」执行——检查 436 口径的稿件时用 `--profile school-436`，默认 `song`，`--heading-scheme black` 可切换。

**Q：为什么我的老稿子突然一堆 FAIL？**
因为专业口径变了。左右页边距从 3.17cm 变成 2.5cm、页眉从"本页一级标题"变成固定文字、表题字号从五号变成小四黑体加粗、表格从三线表变成完整边框、还多了 AI 工具使用声明专节。`--profile school-436` 可以看到按老口径的结果作对比。

**Q：脚本报了 WARN，要我改吗？**
WARN 是"需要你确认"的项目（例如与另一种口径不符、依赖样式而未显式声明边框）。逐条判断：能按学校模板确认的就改，确认可以保留的，在交付说明里写一句理由。

**Q：能查 LaTeX 或 PDF 吗？**
目前只对 `.docx` 做机检。LaTeX/PDF 交付时用同一套细则人工对照，图表编号规则同样适用。
