## 为什么需要它

论文格式被打回，通常不是内容问题，而是这几件小事：📄 目录页码和正文对不上 ｜ 🧾 页眉串了节 ｜ 🔢 图表编号从头到尾连着数 ｜ 📐 摘要题头字号差一号。这些都能被"看出来"，也都能被"查出来"。

这个技能包把 436 号文的要求写成三层：`SKILL.md` 负责判断你要做什么，`references/` 存细则，`scripts/` 直接对 `.docx` 做离线自检——**改完就能验，不用靠肉眼猜**。

## 四个亮点

| | 亮点 | 说明 |
| --- | --- | --- |
| 🤖 | **可机检** | `scripts/check_docx.py` 离线读 `.docx`，覆盖页面、页码分段、页眉、字号、标题编号、题注、目录、摘要、参考文献、装订顺序等 14 类检查，输出 FAIL / WARN / PASS，每条都指到 436 号文的条款 |
| 🧭 | **路由清晰** | `SKILL.md` 先问"你手上是什么"（已有 .docx 要排版 / 只要检查 / 要写作 / 要交付打印），再决定读哪份细则，不用一次吞下整套规范 |
| 📐 | **图表编号强制规则** | `图X-Y` / `表X-Y`：每章从 1 重编，图题在图下、表题在表上，题末不加标点，正文必须先引用——脚本逐条核对 |
| 🤝 | **口径冲突不装懂** | 正文标题的「小 4 加粗宋体」与「黑体」两种口径都写明来源，脚本按你选的口径核对，不一致时给 WARN 让你去找导师确认 |

## 快速开始

```bash
# 1. 装到技能目录（三选一）
git clone <this-repo> ~/.codex/skills/ynufe-thesis-format         # Codex
git clone <this-repo> ~/.agents/skills/ynufe-thesis-format       # 通用 agents 技能目录
git clone <this-repo> ~/.claude/skills/ynufe-thesis-format       # Claude Code

# 2. 对你的论文跑一次自检（Python 3.9+，只用标准库）
python scripts/check_docx.py "我的论文.docx"
python scripts/check_docx.py "我的论文.docx" --json
python scripts/check_docx.py --list-rules
```

脚本**只读** `.docx`，不修改、不上传任何内容。安装后重新开一个会话，技能才会被加载。

## 它能替你查什么

| 规则组 | 检查内容 | 依据 |
| --- | --- | --- |
| `page.*` | A4 开本、上下 2.54cm / 左右 3.17cm、页眉 1.5cm、页脚 1.75cm、1.5 倍行距 | 第十五条（三） |
| `page.numbering` | 前置部分大写罗马数字、正文阿拉伯数字并从 1 重新开始、封面不编号 | 第十五条（三） |
| `header.*` | 除封面扉页外每页有页眉，正文页眉用 `STYLEREF "标题 1"` 取本页一级标题 | 第十五条（五） |
| `style.*` | 正文小 4 宋体 + Times New Roman、首行缩进 2 字符、题目 ≤25 字 | 第十五条（三）、第六条（二） |
| `heading.*` | 四级标题的编号形式（`一、`/`（一）`/`1`/`（1）`）、字体口径、大纲级别、上下空一行 | 第十五条（三）（四） |
| `abstract.*` `keywords.*` | 「摘　要」题头小 2 加粗宋体居中、摘要 300—500 字、关键词 3—5 个、外文摘要 Times New Roman | 第十五条（二）、第六条（三） |
| `toc.*` | 「目　录」题头 3 号加粗宋体、TOC 域为两级、条目字体与页码 | 第十五条（一）、第六条（四） |
| `caption.*` | 编号格式、图题在图下 / 表题在表上、每章连续、正文先引用、题注 5 号宋体 | 第十五条（九）（十） |
| `table.threeLine` | 三线表：无左右边线、上下 1.5 磅、内线 0.5 磅 | 第十五条（九） |
| `note.*` `reference.*` `body.*` `binding.*` | 脚注按页编号、参考文献 ≥20 篇且序号连续、正文 ≥10000 字、装订顺序 | 第六条、第十五条、第二十五条 |

跑完会得到两类提示：

```text
=== 必须修改（FAIL）===
[abstract.heading] sz=32（应 36 即小 2）  —— 摘要题头
[heading.numbering] 编号形式=%1.（应 %1）；suff=None（应 nothing）  —— heading 3

=== 建议确认（WARN）===
[table.threeLine] 内横线 sz=6（应 4 即 0.5 磅）  —— 表块 190
```

脚本不渲染版面，所以**页眉串节、目录点线、图表跨页断开**这些仍要导出 PDF 转图逐页看——技能里把这步写成了硬性交付条件。

## 几条容易被忽略的规则

- **标题编号后缀**：标题自动编号的后缀必须是"无"（`suff=nothing`）。默认的制表符后缀会让目录条目与点线之间空出一大截。
- **三级、四级编号**：`1` 不带尾点；四级是 `（1）` 而且是**全角括号**，并且四级标题样式必须挂上编号，否则正文里根本没有第四级序号。
- **页码分段靠分节**：前置部分罗马数字、正文从 1 重来，只能靠分节符实现；封面单独成节且不引用页眉页脚，才是真的没有页码。
- **摘要题头与目录题头不一样大**：「摘　要」是小 2（18pt），「目　录」是 3 号（16pt）。
- **图题在图下、表题在表上**，题末一律不加标点；正文先写"如图X-Y所示"，图再出现。
- **查重低于 20%**；送检文件名按「学院+专业班级+学号+作者姓名+指导教师姓名+题目」。

## 常见问题

**Q：会上传我的论文吗？**
不会。技能本身没有网络请求，检查脚本在你本机读 `.docx`，只读不写。

**Q：标题到底用宋体加粗还是黑体？**
436 号文第十五条（三）原文是「正文中标题用小 4 加粗宋体」；部分学院模板与导师按「一级二级黑体 4 号、三级四级黑体小 4」执行。两种写法都有真实来源，**以你导师或学院给的模板为准**。默认用 `song` 口径检查，`--heading-scheme black` 可切换。

**Q：脚本报了 WARN，要我改吗？**
WARN 是"需要你确认"的项目（例如与另一种口径不符、依赖样式而未显式声明边框）。逐条判断：能按学校模板确认的就改，确认可以保留的，在交付说明里写一句理由。

**Q：能查 LaTeX 或 PDF 吗？**
目前只对 `.docx` 做机检。LaTeX/PDF 交付时用同一套细则人工对照，图表编号规则同样适用。
