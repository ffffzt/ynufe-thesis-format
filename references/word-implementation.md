# Word / python-docx 实现要点与常见坑

本文件记录在 Word 文档中落地上述格式时容易踩的坑，以及经过验证的做法。所有数值按 A4、左右边距 3.17cm 计算。

## 关键数值

| 项目 | 值 |
| --- | --- |
| 页面 | 宽 11906 twips × 高 16838 twips（A4） |
| 上下边距 | 1440 twips（2.54cm） |
| 左右边距 | 1800 twips（3.17cm） |
| 页眉 / 页脚距离 | 851 / 992 twips（1.5cm / 1.75cm） |
| 正文横向可用宽度 | 11906 − 1800 × 2 = **8306 twips** |
| 字号换算 | Word 的 `w:sz` 单位为半磅：小 4 = 24，4 号 = 28，小 3 = 30，3 号 = 32，小 2 = 36，5 号 = 21，小 5 = 18 |
| 首行缩进 2 字符 | 小 4 正文下约为 480 twips（`firstLineChars="200"`） |

## 坑 1：正文样式的首行缩进会污染封面、目录和页眉

中文论文的正文样式（Normal）通常带 2 字符首行缩进。封面信息栏、目录条目、页眉等如果继承该样式，会被整体推右，出现错行、串行、下划线跑到下一行等现象。

**做法**：给这些段落显式写入 `w:ind w:firstLineChars="0" w:firstLine="0"`，覆盖继承值。不要只设 `firstLine` 而不设 `firstLineChars`——`firstLineChars` 优先，仍会按字符数缩进。

## 坑 2：标题编号的后缀决定目录条目是否有空档

标题自动编号默认后缀是**制表符**（`w:suff` 缺省即 tab）。生成目录时，这个制表符会一起进入目录条目，在条目和点线之间留下一个明显的空档（例如「一、　　　　绪论……1」）。

**做法**：把各级标题编号的 `w:lvl/w:suff` 设为 `nothing`，编号与标题直接相连（「一、绪论」）。该设置同时影响正文标题，属于预期行为，应与学校模板保持一致。

## 坑 3：页码分段必须用分节

声明、摘要、目录用罗马数字，正文用阿拉伯数字并从 1 重新开始，必须分成不同**节**，不能只插分页符。

- 节属性 `w:sectPr` 放在**该节最后一个段落的 `w:pPr` 内**；文末最后一节的 `w:sectPr` 是 `w:body` 的直接子元素
- 罗马数字节：`w:pgNumType w:fmt="upperRoman" w:start="1"`
- 正文节：`w:pgNumType w:start="1"`（阿拉伯数字）
- 封面单独成节并**不加**页眉页脚引用，即可实现无页眉、无页码

## 坑 4：页眉按节继承，容易串页

若某节不写页眉引用，会**继承上一节**的页眉。想在某节显示不同页眉（或完全不显示），必须为该节显式指定页眉引用，或显式取消链接。

- 正文页眉用 `STYLEREF "标题 1" \n \* MERGEFORMAT` 字段自动取本页一级标题
- 前置部分各页若要显示「原创性及知识产权声明」「摘　要」「Abstract」「目　录」等，最稳妥的做法是**各拆为独立分节**，每节独占自己的页眉
- 页眉格式：居中、5 号宋体（`w:sz w:val="21"`）、下加细边框

## 坑 5：带分节符的段落无法随标题折叠

Word 折叠标题时不会把承载分节符的段落收进去。如果「关键词」段落本身带 `w:sectPr`，折叠「摘　要」时正文收起、关键词却留在外面。

**做法**：让分节符落在关键词段落**之后**的一个独立空段落上（字号可设为 1 磅，视觉上不可见）。这样关键词就是普通正文段落，能随标题一起折叠。

## 坑 6：目录域与更新

- 目录域代码：`TOC \o "1-2" \h \z \u`（两级、带超链接、隐藏 web 版页码与制表符、使用大纲级别）
- Word 中可用 `TablesOfContents(1).Update()` 或 `Fields.Update()` 更新；更新后页码、条目才会正确
- **更新域会重置条目格式**：Word 会按自己的规则重新套用 TOC 1 / TOC 2 样式并加段落级覆盖。若要目录点线粗细、缩进完全一致，需要在更新之后再统一一次条目格式
- 前置部分（声明、摘要、Abstract）要出现在目录里，需要给对应标题段落设置 `w:outlineLvl`（如 `val="0"`），但不参与章节自动编号

## 坑 7：目录点线不统一

点线由段落的右对齐制表位（`w:tab w:val="right" w:leader="dot"`）绘制，位置应等于**正文右边界**，即 **8306 twips**。

点线粗细/疏密不一致通常不是制表位问题，而是各条目的**字号不一致**——点线按段落标记的字号绘制。例如首个条目的段落标记是 11pt、其余是 12pt，看起来就会一条粗一条细。

**做法**：统一所有目录条目的字号（正文小 4 = `w:sz w:val="24"`），并统一段落标记的格式；一级条目顶格、二级条目左缩进 2 字符（`w:ind w:left="480"`），两级的缩进都要显式写 `firstLineChars="0" w:firstLine="0"` 以抵消正文样式的首行缩进。

## 坑 8：表格拆分与表头重复

长表格跨页时，需要把表头行设为重复标题行（`w:tblHeader`），否则第二页没有表头。表题在前、表格在后，且表题与表格之间不要插入空段落。

## 坑 9：导出核对

docx 的文本提取无法反映版面。修改后应导出 PDF 并转成页面图片逐页检查，重点看：目录点线是否对齐、页眉是否串节、页码是否连续且分段正确、图表是否跨页断开、题注是否与图表分离。

## 参考实现：一份可用的分节与页眉布局

下面是从一份云南财经大学本科毕业论文（新稿，一二三章已完成）里读出来的真实结构，可直接照抄这一骨架：

| 节 | 内容 | 页码格式 | 页眉 |
| --- | --- | --- | --- |
| 1 | 封面 | 无 `pgNumType`、无页码域 | 无 |
| 2 | 原创性及知识产权声明 | `upperRoman` start=1 | 固定文字「原创性及知识产权声明」 |
| 3 | 摘　要 | `upperRoman` 续编 | 固定文字「摘　要」 |
| 4 | Abstract | `upperRoman` 续编 | 固定文字「Abstract」 |
| 5 | 目　录 | `upperRoman` 续编 | 固定文字「目　录」 |
| 6 | 正文及以后 | `decimal` start=1 | `STYLEREF "标题 1" \n \* MERGEFORMAT` |

同一份文档里核对到的其他事实，可作为默认值使用：

- 页脚域：前置部分 `PAGE \* ROMAN \* MERGEFORMAT`，正文 `PAGE \* MERGEFORMAT`，页脚段 `jc=center`
- 前置部分**每个部分单独一节并各自挂页眉**是最省心的做法；共用一个节会让页眉串页
- 正文样式的首行缩进为 `firstLineChars=200 / firstLine=562`；标题样式必须显式写 `firstLineChars=0 firstLine=0` 抵消它，否则封面、目录、页眉会被整体推右
- 标题编号的 `suff` 必须是 `nothing`；缺省（制表符后缀）会让目录条目与点线之间出现空档
- 三级标题的 `lvlText` 应为 `%1`（无尾点），四级为 `（%1）`，且四级标题样式必须挂上 `numPr`——不挂就没有任何编号
- 题注段落字号设 5 号（`sz=21`），与正文小 4 区分
- 「摘　要」题头按 436 号文用小 2（`sz=36`），「目　录」题头用 3 号（`sz=32`），两者不同，不要写成一样大
- 「目　录」题头单独设 `outlineLvl=3`，让它不出现在自己的目录里；正文标题用 `outlineLvl=0…3`

## 脚本能查什么、查不到什么

`scripts/check_docx.py` 覆盖：节级页面参数与页码格式、页眉域与格式、Normal 与 heading 1—4 的字体字号、标题编号（`numFmt`/`lvlText`/`suff`）、一二级标题上下空一行、摘要题头与字数、关键词数量与标签、目录域层级与条目字体、题注格式/位置/序号/引用、三线表边框、脚注编号方式、参考文献数量与序号、正文长度、装订顺序。

它读的是 OOXML 与样式定义，因此下面这些查不到，必须渲染后人工看：

- 目录点线的实际观感、缩进与对齐
- 图表是否跨页断开、题注是否与图表分离
- 页眉在首页/奇数页/偶数页的实际显示（`titlePg`、`evenAndOddHeaders`）
- Word 里的域是否已更新——页码、`STYLEREF`、`TOC` 都是域，改完必须更新才会正确
- 封面模板、声明页、签名图这类图片内容的合规性

所以：**脚本无 FAIL 只是必要条件，不是交付条件。**
